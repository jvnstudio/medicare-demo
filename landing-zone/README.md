# Medicare GCP Landing Zone — Fabric FAST v58.0.0

This directory builds the **landing-zone layer first** using Google Cloud Foundation Fabric FAST. The `terraform/` workload demo is Layer 2 and should be adapted to consume FAST-created projects/network contracts after the landing zone is working.

## Architecture sequence

```text
GCP Organization
  |
  +-- FAST Stage 0: Organization Setup
  |     +-- organization/folder hierarchy
  |     +-- organization policies and IAM
  |     +-- centralized logging foundation
  |     +-- IaC projects, state buckets, service accounts
  |     +-- GitHub Workload Identity Federation contracts
  |
  +-- FAST Stage 1: VPC Service Controls (optional / requirements-driven)
  |
  +-- FAST Stage 2: Networking
  |     +-- Shared VPC host projects
  |     +-- primary/DR networking
  |     +-- DNS/firewall/hybrid connectivity foundations
  |
  +-- FAST Stage 2: Security
  |
  +-- FAST Stage 2: Project Factory
        +-- Medicare application/service projects
        +-- Shared VPC attachment
        +-- workload service accounts / CMEK integration

Then the workload layer deploys Compute Engine MIGs, GKE, storage and DR into governed application projects.
```

## Prerequisite

A real FAST landing zone requires a **Google Cloud Organization**. A standalone project cannot substitute for it because Stage 0 manages organization IAM, policies, folders, tags, projects, and shared foundations.

FAST works best with an empty/sandbox organization. Brownfield organizations require preservation/import planning before apply.

## Phase A — Discovery

From the repository root:

```bash
export PROJECT_ID="$(gcloud config get-value project)"
bash landing-zone/scripts/01-discover-fast.sh "$PROJECT_ID"
```

If discovery reports no organization or billing account, stop. Otherwise export the exact `FAST_...` values it prints.

Optional defaults:

```bash
export FAST_PREFIX="medlz"
export FAST_PRIMARY_REGION="us-east4"
export FAST_GITHUB_REPO="jvnstudio/medicare-demo"
```

## Phase B — Prepare FAST Stage 0

```bash
bash landing-zone/scripts/02-prepare-stage0.sh
source landing-zone/.fast.env
```

The script pins Cloud Foundation Fabric to `v58.0.0`, enables documented bootstrap APIs on the temporary billed project, preserves Google's Classic dataset, and generates Medicare-specific `defaults.yaml`, `cicd.yaml`, and Stage 0 tfvars.

Inspect them:

```bash
cat landing-zone/generated/defaults.yaml
cat landing-zone/generated/cicd.yaml
cat landing-zone/.fabric/fast/stages/0-org-setup/0-org-setup.auto.tfvars
```

## Phase C — Review bootstrap IAM

Dry run only:

```bash
bash landing-zone/scripts/03-grant-bootstrap-roles.sh
```

If you are authorized to administer the sandbox/demo organization and the grants are correct:

```bash
bash landing-zone/scripts/03-grant-bootstrap-roles.sh --apply
```

A `PERMISSION_DENIED` means the active identity lacks bootstrap authority. Do not work around that by dropping to project scope.

## Phase D — Stage 0 plan and apply

Create a saved plan:

```bash
bash landing-zone/scripts/04-stage0.sh plan
```

Review the plan carefully. Stage 0 contains organization-, folder-, project-, IAM-, policy-, logging-, and IaC-level changes.

Only after review:

```bash
bash landing-zone/scripts/04-stage0.sh apply
```

The helper requires typing `APPLY_FAST_STAGE0` before applying.

Then inspect outputs:

```bash
bash landing-zone/scripts/04-stage0.sh outputs
```

## Phase E — Backend/provider migration

FAST uses two apply cycles. The first apply uses the bootstrap identity and temporary quota project. Stage 0 then creates dedicated IaC identities/backends and generated provider contracts.

After the first apply:

```bash
source landing-zone/.fast.env
cd "$FAST_STAGE0_DIR"
../fast-links.sh "$FAST_OUTPUT_DIR"
```

Use the **actual generated** `iac-0` project/provider output to migrate state:

```bash
terraform init -migrate-state
terraform apply
```

Do not guess generated project or provider names before Stage 0 has produced them.

## After Stage 0

Proceed in this order:

```text
Stage 0 Organization Setup
  -> Stage 1 VPC-SC (if required)
  -> Stage 2 Networking
  -> Stage 2 Security
  -> Stage 2 Project Factory
  -> Medicare workload layer
```

Do not deploy workload Terraform into the temporary bootstrap project once FAST application projects exist. Refactor the workload layer to consume the project IDs, Shared VPC subnet links, KMS keys, and other contracts generated by FAST.

## Demo dataset choice

This repository starts with the **Classic FAST dataset** because it is easier to explain during a live architecture demonstration. Hardening can be added after the foundation is working.

## Cost and blast radius

FAST Stage 0 can create multiple projects/shared resources and modify organization-level IAM/policies. Use a sandbox organization where possible and review every Terraform plan before apply.
